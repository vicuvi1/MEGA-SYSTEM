# Day planner and calendar

> Plan from now, the plan editor and Google/Todoist sync, plan expiry, calendar layout, focus blocks vs events.
> Copied out of [`docs/AI_HANDOFF.md`](../AI_HANDOFF.md) on 2026-11-07, so an agent can read only its own area.
> This file is now the maintained copy for this area: update it, not the big handoff. Start at [`docs/INDEX.md`](../INDEX.md).

- **A plan starts from now (`src/core/planShift.ts`).** `planStartAt` (now rounded up to 5 min + 5); the packer, the planner and Regenerate never put a block in the past; `shiftPlan` moves past, unstarted blocks into the time left (must-dos and his asks first; fixed events stay; what doesn't fit stays on today's list). The plan cards offer "You're starting at 10:00 … Shift the plan?" (Shift / Keep, `rhythm('shift')`, which also moves an approved plan's calendar blocks), and asking for the plan again shifts an approved late plan by itself. **His asks stay today:** a task he asks Ben to add for today (his words, `@today`, or due today) goes into `plan_asked`; the packer places those (and ⭐ tasks) first, swaps out an older, lower-priority block if the day is full, and otherwise keeps it on today's list and asks with chips (`squeeze`).

- **Editing the plan in its card (`src/renderer/src/plan/PlanEditor.tsx`, `planStore.ts`; pure logic `core/planEdit.ts`, `planSync.ts`, `planUndo.ts`, `planCheck.ts`).** The Coach plan card and Today → Plan show the blocks as a day column: drag to move (5-minute steps), pull the bottom edge, double-click to rename, ✕, "+ Add block" in a free gap, drag a task row onto another block, 📌 pin, a tick per block (or "Approve until 14:00") to approve part of the plan; mouse, touch and keys (↑↓ move the focused block 5 min, Shift+↑↓ its length, Enter rename, Delete, P pin). Each block has an `id`; `sync` remembers what Google and Todoist hold (event id, times, task ids), so the work is the difference, sent ~400 ms after the last edit (one call per block), with a status per block (syncing… / ✓ / ⚠ Retry). Only approved blocks reach the calendar and task times (a draft syncs once approved); a tick closes the task in Todoist (`closed`), an untick reopens it and gives back its points. Deleted blocks wait in `removed` until their event is cleared. Undo (button, toast, Ctrl+Z; 20 edits) puts the plan back with today's `sync` (`rebase`), so Google and Todoist follow. Two-way: every ~60 s while the page is visible, on focus and on `life-external-changed`, `mergeRemote` takes in events moved/renamed/deleted in Google and tasks moved/closed in Todoist ("Updated from Google" toast); a block with an edit not sent yet wins (it's newer). Pinned blocks (and approved ones already in the calendar) never move: not by a drag, the shift, "Re-plan from now" (`replanFromNow`, also the chat words "re-plan from now", `rhythm.replanNow`) or Regenerate (`keptAsEvents` + `mergeKept` in `propose`). **QA1:** `checkPlan` (overlaps with blocks and fixed events, a break every 90 min of deep work, 30 min for lunch, a water goal, ending before bedtime minus 45 min of wind-down, not more than the free time, nothing in the past) runs on every card; `fixPlan` fixes what it can before `propose` saves, and the card's chip ("2 blocks overlap — fix?") runs it on tap. Approval records each block's event (`sync.eventId`); an older approved plan finds its events by name and start (`linkEvents`).

- **Plans expire (`rhythmFor`).** A draft never approved expires when the app day turns (04:00) or when an older planner made it (`briefing.planner` < `PLANNER_VERSION`); it shows folded as "Expired · last night's draft" and the Coach page asks for a fresh proposal once. Only plan cards from today's app day are live.

**Calendar layout and event details.** Today's "Your day" (`DayStrip.tsx`) and the Calendar page's day/week views share one layout engine, `core/calLayout.ts` (tested): overlapping events sit side by side in equal columns (widening into free ones), a short event is drawn at least 24 px tall and laid out that tall, long "window" events become a band behind the rest, more than 3 at once fold into "+N". A click (under 5 px of movement; more is a drag) or Enter opens `EventSheet.tsx`, shared by both: details (time, calendar, place, call link, people, repeats, notes, event or focus block) and Edit, Mark done (the same marks as the ✓), Start timer (focus blocks), Move to…, Delete (asks; Undo). Edits show at once, go to Google through `life.google.update/move/remove`, and can be undone; repeating events ask "This event / All events". On a phone it's a bottom sheet.

- **Calendar items: focus blocks vs events (`core/blockKind.ts`).** A focus block (Life System's own, or a deep-work title) keeps the timer flow; an event (a class, a commute, a meeting, an appointment, anything else from Google) gets ✓ Done / Didn't go, no timer, no auto-start, no "back to it?" and one "Did you go?" after it ends. Your choice per title (island ⋯ menu, or Event / Focus block in an event's details) is the synced setting `block_kinds`; the ✓ is the same `block_marks` the Today timeline uses, so it shows in both. No points for an event. The island's morning card hides the wake-up ask once today's sleep row has a wake time from anywhere (`wakeLoggedToday` in `core/sleep.ts`).

- **One event per block, by kind, and free time kept (`core/planLook.ts`, 2026-11-07).** A block's Google event has the block's own id (`planEventId(day, blockId)`, letters a–v and digits as Google wants), so the approval (`rhythm.approve`, which now gives blocks their ids first) and the plan editor's sync can both write it and Google keeps one event: `create` with an id that exists already updates (and undeletes) it (`src/server/googleCalendar.ts`). The old double came from "Approve all": the approval saved "approved" before its events, the editor saw approved blocks with no event and made them too. Events get an emoji and colour by kind (`blockLook`: 🎯 deep 9, 📚 study 7, 🧹 chores 5, 💪 sport 10, ☕ break 2, 🍽️ meal 6); the emoji is not part of the block's name (`plainTitle` in `mergeRemote`, `linkEvents`, the shift). Once a day per device `planStore.cleanOnce` quietly removes copies the app made (marked `ours`, same title, start and end; the block's own event stays; your events are never touched). The packer (`packDay`) keeps a 30-min lunch between 12:00 and 14:00 (`keepMeal`), 15 min after a deep block of an hour or more, and leaves at least `freeShare` of the free time unplanned (My life → Free time, default 15%, `LifeFit.freeShare`); quick tasks in the work window don't count against it. `checkModelPlan` falls back to the packer when the model fills the free time; `checkPlan` flags `nofree` ("Only 20 min free").
- **Sync on the plan card.** The plan editor bar (so the Coach chat plan card and Today → Plan) shows `PlanSync` (`plan/SyncButton.tsx`): the Sync button plus "Auto-sync on · last checked 12:04" (wording in `src/core/syncLabel.ts`). While a plan card is on screen it checks by itself every 60 s while the page is visible and at once when you come back (focus or visibility). After 2 failed checks in a row the line says "Can't reach Todoist, retrying"; a failed manual Sync shows an error with Retry. The "Updated from Todoist" toast is the existing `planStore` notice and appears only when something really changed. Smoke: "Sync button".
- **One thing = one block (`core/planDedupe.ts`, 2026-11-08).** The same thing reaches the planner from several places (a Todoist task and its app copy, a habit or class in the calendar, a promise, a pinned block). Two titles are the same thing when they have the same id, or the same words once case, punctuation, the emoji in front, a length ("(20 min)", "· 45 min", "1h") and "today" are taken off; "Weekly review: plan the week" also matches the "Weekly review" event because the words before ":" count when they are 2+ words (so "University: read ch. 3" is not swallowed by a "University" class). Other numbers stay ("chapter 3" ≠ "chapter 4"). **What wins:** a pinned or approved block, then a calendar event still ahead today (not declined, not one the app made, not already over), then the loose copy. `packDay`: tasks merge by id then title (the most important copy stays, keeping ⭐/asked); a task that is an event gets no block and is not picked as a must-do (last night's top 3 still can be), and sits in "Also today" with `event` ("at the 17:00 event"); a workout event means no extra training slot. A group block is named "University: first task +2 more" (its tasks are its checkboxes). `dedupePlan` runs again at the end of `propose` on whatever made the plan (packer, model, last night's draft, kept blocks): a task in two blocks stays in the first, a block named like an event or like an earlier block goes, "Also today" holds each task once and never a must-do. A task in a block is shown with its block only: the card's "Also today" and the Telegram text list just tasks without a block (the plan still keeps them in `also` with `at` for ids and relinking), and the headline counts only those. A deleted block's event waiting to be cleared (`removed`) is not a fixed event for the next plan, and a task whose time was synced back as a calendar event (Todoist's calendar) matches that event instead of getting a second block. Idempotent: cleaning or planning twice gives the same plan. Nothing is deleted from Todoist, Google or the database, and no points change. Past calendar events still show hatched on the card as context; they are not blocks.
- **Sync button and Todoist refresh.** "Sync" (`plan/SyncButton.tsx`) on Tasks and in Today → Now's other tasks: `life.syncNow()` (task edits still waiting for Todoist are sent first, then Todoist's change check, the calendar cache dropped, `life-external-changed` so every list reads again, completed tasks paid through `todoist.sync(true)`), then `planStore.checkRemote(true)`; "Synced 12:04" after. The live loop in `tursoWebBridge.ts` asks Todoist "anything new?" every 5 s while you use the page and every 60 s otherwise (it was 10 minutes after 15 idle minutes: a task added in the Todoist app while the page sat idle stayed missing), every 5 min in the desktop tray, and at once on window focus (alt-tabbing back from Todoist fires no visibility change). The change check has its own failure pause (`changesBreak`), so its failures no longer pause the list reads, and a failed read keeps the last list (`web/todoRefresh.ts`) instead of showing none.
- **Plan sync rules for Todoist changes (`mergeRemote` with `where` and `idOf`, 2026-11-09).** Every block with tasks is checked, drafts too (they hold titles only: the id comes from what the plan and today's list taught `planStore`). A task missing from today's list is looked up (`life.todoist.lookup`: the change check's answer, else `/api/todoist {op:'lookup'}`): **done** (also a recurring task done today that moved on to its next date) → ticked in its block and added to `closed`, never closed twice and never paid by the plan; **moved to another day or its date taken off** → it leaves the block and is listed under "Moved to tomorrow" with "moved to tomorrow in Todoist" / "moved to Thu 19 Nov in Todoist" / "has no date in Todoist now" (back on today in Todoist, it leaves that list and the audit puts it back on today's list); **deleted** → it leaves the block, nothing is ticked; **not known** (Todoist did not answer) → left alone, never guessed. A block whose every task left goes too (never a stale block); an approved one's calendar event is cleared through `removed`, and the tasks are not written back (they keep their new day). A **pinned** block stays where you put it; only the task leaves it. **Renamed** in Todoist → the block's task list, its title (when it was the task's name), its sync memory (so no rename is sent back) and the must-dos take the new name; Google's event title follows next round. A time change on an approved block's task works as before (a one-task block follows the new time). The must-dos and "Also today" drop a task that moved away or was deleted. The check runs on every Todoist change the live loop sees (`life-todoist-changed`, no 20-second pause), when a plan card opens, and on Sync (which waits up to 3 s for edits on their way instead of skipping). The plan card's must-dos, "Also today" and "Moved to tomorrow" read the plan store's copy (`plan/useLivePlan.ts`), so they change with it.
- **The plan audit (`core/planAudit.ts`, 2026-11-08).** `auditPlan` runs when a plan is made (`propose`, after `fixPlan`; it replaces the old last `dedupePlan` call), after you place a block by hand (move, stretch, add: that block stays where you put it, the others make room; blocks in the past are left for "Shift the plan?"), on "fix?" and, without moving anything, on every render of the card. It: cleans with `dedupePlan`; puts any open task of today that is nowhere in the plan back on today's list (never dropped; not one you took off the plan by hand, see `dropped`, and not one already closed); moves a block whose task has its own time today ("by 15:00") into a gap before it (a time the plan itself gave the task in Todoist is not a deadline); runs `fixPlan`; and when there is more work than free time gives up only the minimum: the least important loose draft (`blockRank`: small tasks, then other focus work, then goal time) is shortened by just the overflow (never under 25 min), and only if that can't do it does it leave the plan, its tasks on the list. Must-dos, what you asked for, overdue, P1–P2 and tasks with their own time today (rank 0–1) never leave, nor pinned, approved, ticked or calendar blocks, and the plan is never emptied. What it can't fix is the chip, plus one plain line: "1 task didn't fit: Lab report. Move it to tomorrow?" (`leftTasks` + `auditLine`; only tasks with "no room today" count, not ones "at the 17:00 event", "waiting on you" (`squeeze`) or already moved to tomorrow). **Move to tomorrow** takes them off today's plan into "Moved to tomorrow" (`moveToTomorrow`, Undo puts the plan back) and gives the Todoist task tomorrow's date; Undo puts the plan back and gives each task its old date again (a toast says so, or says which Todoist did not take). Idempotent. `checkPlan` now counts overlapping events once (a call inside a work window was counted twice, so a light day looked "too much").
- **Why each block is there (`blockWhy`).** One muted line under the block's name (blocks 34 min or longer), at most two reasons, only from data the plan or Todoist holds: pinned, today's workout, you asked for it today, due 15:00 (the task's own time), due Friday / due in 9 days, overdue, must-do, from Todoist: P1–P3, goal time for today, "3 small tasks together", else "from Todoist · University". Nothing when there is nothing true to say.
- **Re-plan by itself (`core/planAuto.ts`, `planStore.maybeAuto`, 2026-11-08).** When the day changes, the DRAFT part the change hits moves and nothing else: a draft the clock passed (10 min grace) that wasn't started (no focus session began in it), a draft that now sits on a calendar event (added, moved, or one that ran long) or on a block still being worked on past its end, and a new P1/P2 (or asked) Todoist task gets a free gap when there is one. Blocks the change doesn't touch stay put (the manual "Re-plan from now" packs everything again; this doesn't). Moving blocks go most important first (`blockRank`). When what has to move is more than the free time left, each is capped at an hour first so the important ones all keep a block. A block with no full spot takes a shorter one if it keeps at least half (and 25 min); else a less important draft that stays gives way (it goes on the list, "to make room for …"); else the biggest window of 25 min+; only then does it go on the list (the audit line offers tomorrow). Test: a crowded day like the smoke fixture keeps the must-dos and the overdue P1 task as blocks (`planCrowded.test.ts`). One note and Undo: "Moved 'Lab report' to 15:40 because Call with the tutor ran long" shows as a toast and as a line on the card until it can no longer be undone. Never moves pinned, approved (whole plan or the block's own tick) or calendar blocks, ticked blocks, or events; never puts back what you removed (`dropped`, filled by the ✕ edit); drafts don't sync, so it sends nothing to Google or Todoist. **When:** on the card's 60 s look, on focus, after `life-external-changed`, after a plan comes in (`attach`); after Google/Todoist changes are merged (`mergeRemote` first, then the re-plan). **Limits (`autoAllowed`):** at most once in 2 minutes, 5 a day (`ls.planAuto` on the device), never while a block is dragged, stretched or renamed, and not within 2 minutes of your own edit; the same inputs give the same plan and a run on its own result changes nothing; a run that would put back what the last one moved (A → B → A) is refused (`isFlipFlop`). **Setting:** Coach → Daily rhythm → "Re-plan by itself" (`RhythmPrefs.autoReplan`, default on). Off: nothing moves by itself and the "Shift the plan?" prompt shows as before; on, that prompt shows only for late approved blocks. Smoke: "Plan trust".
- **Sync-conflict rule (re-plan by itself).** Google and Todoist first, then the automatic re-plan: a look merges remote changes (`mergeRemote`; a block with an edit not sent yet still wins), and only then may the re-plan run, on the merged plan. It never runs while edits wait to be sent (`sender.pending()`) or a remote check runs. Because it only changes drafts, it never writes to Google or Todoist, so it cannot fight the other device or the phone; once you approve a block, only you or the outside apps move it.
- **Time limits (`core/planLimits.ts`, 2026-11-08).** Coach → Daily rhythm → Time limits (synced setting `plan_limits`, editor `plan/PlanLimits.tsx`): most work a day (default none), an off time (nothing planned ends after it), protected blocks of a fixed length on set weekdays (training 45 min at 18:00 Mon/Wed/Fri, lunch), and a cap per kind (study, deep work, small tasks; the kind is the block's look from `planLook`). Work = every block that is not training, a break or a meal. Protected blocks are fixed time like a calendar event (`withProtected`; one already in the calendar at that time is not added twice) and show striped green in the plan column. **Who keeps them:** the packer (`packDay({ limits })`: the off time ends the day, each placement stays under the work limit and its kind's cap; a quick batch in the work window counts once a work limit is set), the audit (`auditPlan`, step 5 `keepLimits`: the least important loose draft still ahead is trimmed, never under 25 min, else goes back on the list), the automatic re-plan (never moves a block past the off time or onto protected time; a new P1 task gets no block when the work limit is full) and `checkPlan` (chip "4h30 of work, your limit is 4h — fix?", "Runs past 20:00 (your off time)"). A workout slot the planner put past the off time or on protected time leaves the plan (the workout itself is untouched). Pinned, approved, ticked and calendar blocks are yours and are never trimmed. When the limits change, or a plan comes in, the plan card trims the draft once with one note ("Kept your limits: off at 20:00, 3h of work") and Undo (`planStore.keepLimitsNow`). Nothing is sent to Google or Todoist (drafts don't sync).
- **Deadlines planned backward (`core/planDeadlines.ts`, 2026-11-08).** The data is the existing deadline goals (focus goals with subject, deadline and hours: "Etica exam on 20 Nov, needs 8 hours"). The hours left (today's minutes done count toward today) become sessions of 25–90 min over the days before the deadline (never on it): `n = ceil(left / 90)` days picked evenly from the day before the deadline back, the heaviest day of the week plan in each stretch first, then any day with room. **One session per deadline a day, at most 90 min** (a second block of the same name would be merged away by planDedupe). A day's room for deadlines (`planWeek.dayRooms`): free time between events from 08:00 (now, today) to the off time or 22:00, minus the free share, times 0.8 on a heavy day, 0.5 normal, 0.3 light, never more than the work limit or the study cap; earlier deadlines take room first. Session id `dl-<goal>-<yyyymmdd>` and the title "Subject: title" (the focus timer counts it), so planning again never makes a second session. Today's session goes into `packDay` as a goal block with its `why` ("exam in 5 days, session 2 of 4", shown by `blockWhy`; the AI naming keeps its name). What can't fit is said plainly: "Etica exam: not enough room before Friday 20 Nov: 3h short." plus "You are behind by 2h." when behind a steady pace; it shows on Today → Week, in Coach → Plan → Deadlines and in the plan's why line. A missed session needs nothing special: the hours left grow and the next plan spreads them over the days left; "Re-book all" (`rhythm.bookGoals`) books the same sessions into the calendar within the off time and around protected blocks. Last night's draft is not used when it lacks today's session.
- **Week plan (`core/planWeek.ts`, `plan/WeekPlan.tsx`, 2026-11-08).** Today → Week shows the next 7 days (today first): each day's kind (tap: normal → heavy study → light) and gym day, planned work against the day's limit (today: today's plan; ahead: deadline sessions) and the deadlines' coverage ("26h in 18 sessions: covered" or how short). Synced setting `plan_week`: a standing weekday template (it holds every week until you change it). Each morning's plan follows it (`dayRules`): a light day caps work at 2h (your own limit can make it lower), heavy days get deadline sessions first, and once any gym day is set the workout slot is planned on gym days only. Changing the week re-plans only draft days: today when its plan is still a draft (a new proposal; pinned blocks stay), and the days ahead (worked out when needed). An approved today stays ("the change counts from next week"); the past is not shown and never changes. Smoke: "Plan limits".

- **Plan speed (2026-11-08): quick-add in words, "Too much today", a fit hint on drag.**
  - **Quick-add (`core/quickAdd.ts`, box on the plan card).** One line becomes a task: "lab report tomorrow 2h", "gym 18:00 45 min", "call mom at 7pm", "essay friday 3h p1", "read 20m". `parseQuick(text, {today, now})` is pure and English-only; it takes typos ("tomorow", "2 h", "45min", "wensday"), 24h and am/pm, a range "18:00-18:45", weekdays ("next friday", "on mon"), dates ("20 nov", "in 3 days", ISO), lengths ("1h30", "1.5h", "half an hour") and p1-p4 (p1 = Todoist 4). It never guesses: when a word could mean two things it returns ONE short question (`ask`) and nothing is saved ("at 7": morning or evening?; "friday" said on a Friday: today or next Friday?; a time already passed today; two different days, times or lengths; no title). The box shows a preview chip ("Lab report · tomorrow · 2h · P1") and, for today, where the block will go ("goes 15:00-15:20"); Enter saves, with a toast and Undo (the plan edit and the Todoist task). The task goes through `life.todoist.quickAdd` with `todoistText(...)` ("Lab report tomorrow p1 for 120 min"). A task for today also gets a draft block placed by `placeQuick` (`core/planFit.ts`): at the time said when it fits, else the nearest free gap, never past your off time or over a work limit or cap; no room means it stays on today's list and the toast says so. A placed block carries the time (approving it gives the task that time), so the task is sent to Todoist without one (a time on the task itself would read as a deadline to the plan audit). **Coach chat (`chatQuickAdd`, a small hook in `webBots.ts` before the model):** only lines that start with "task", "todo", "quick add" or "+" ("+ read 20m"); an unclear one gets the question. Everything else ("add ...", "gym at 18:00") stays with Ben, who reads those as events or questions. A task for today is remembered as his ask (`plan_asked`) and the reply offers "Re-plan from now".
  - **Too much today (`tooMuchToday`, button next to the box).** Keeps every pinned, approved, ticked, calendar and past block, the must-dos and what you asked for today; then the most important of the rest (`blockRank`, earlier first) while the day's work stays inside a budget: the least of your work limit and 75% of the free time left. The rest moves to tomorrow, whole blocks at a time, plus tasks listed with "no room today" (never a must-do). It is the existing Move to tomorrow (`planStore.moveTomorrow`): Todoist gets tomorrow's date, and one Undo (the card's line, the toast, Ctrl+Z) gives back the plan and every old Todoist date. A line under the box says exactly what moved ("Moved 2 to tomorrow: Tidy notes (45 min), Book dentist (30 min)"); "Today already fits: nothing to move" when nothing has to. Each draft block also has a ⋯ menu with "Move to tomorrow" (and Rename); not on pinned, approved or calendar blocks.
  - **Fit hint on drag (`fitVerdict`, `nearestSlot` in `core/planFit.ts`).** While you move a block, stretch it, or drag a task row onto the empty day column, the drop zone says "Fits · 45 min free" (green, the free window around it) or "Doesn't fit: overlaps Lecture" / "over your 6h limit" / "over your 17:00 off time" / "runs past 21:00" / "that time has passed" (red). Same rules as the card's checks: blocks, fixed and protected events, off time, work limit, caps. A block dropped where it doesn't fit goes to the nearest free gap (toast with Undo) or is refused when nothing else fits; a stretch that doesn't fit is refused. A task row dropped on the column becomes its own block (`dropTaskAt`), same rule. Dropping it onto another block still joins that block. Never silently on top of something.
  - **Today → Plan is compact.** The plan bar is one row (status, warning, Sync, Undo, a ⋯ menu holding "Re-plan from now"), Sync's "Auto-sync on" line sits under it, "Approve until" is one line, and the audit and auto notes keep their button on the same line. Smoke "Today tabs" holds at 1.75 screens (plan 1.73). Smoke: "Plan speed".

- **The planner learns from what really happened (2026-11-08): end-of-day check, learned task times, plan score.**
  - **End-of-day check (`core/planReview.ts`, `plan/PlanReview.tsx`).** A sheet with today's work blocks that have started (training, breaks and meals left out), one tap each: **Done** (ticks the block, so its Todoist task closes through the plan's usual tick: points only from that existing path), **Partly** (how many minutes), **Tomorrow** (the usual Move to tomorrow with `keepBlocks`: Todoist gets tomorrow's date, the block stays on today's plan as what was planned, its calendar event too) and **Drop** (only noted; nothing is deleted, the task stays open in Todoist). Done and Partly show a minutes box. Where it opens: "Shut down my day" (a "Check today's plan blocks" button in the shutdown card; in the evening Ben's day review replaces the plan card on Today), the plan card's bar ("✓ Check the day", once the last work block is over, `reviewOpen`) and the bar's ⋯ menu any time. **Real numbers win:** the focus timer's minutes per block (`timerFor`: a session counts for the block whose name it carries, else the block it mostly sat in, each session once), then minutes you type (`src: 'said'`); with neither, nothing is assumed (`src: 'plan'`). Blocks you ticked during the day are noted as Done when the check opens. A new mark takes back the old one's effect (Done → anything else unticks, which reopens the task and gives back its points as before; Tomorrow → anything else gives the task today's date again). Undo on the card takes back the plan edit and the mark together. Records: synced setting `plan_review` (`{ v: 1, days: { [day]: { items: { [blockId]: … } } } }`, one record per block, so marking twice changes nothing; the last 90 days are kept; `mergeReview` keeps the newer mark per block). The check itself pays nothing. Telegram (next builder): `reviewRows`, `reviewItem`, `putItem`, `reviewLine`.
  - **Learned task times (`core/taskTimes.ts`).** A kind of task is named by its words (the first two that mean something, then the first: "lab report", "lab"; filler, numbers and lengths dropped, light stemming so "reading" = "read"), its Todoist labels and its project (in that order, most specific first). A sample is a Done block of one task with a real number (timer or typed); its ratio is real minutes ÷ the planner's own plain guess for that title (`estimateMinutes`), not ÷ the block's length, so the learning never chases its own earlier output. Per kind: the median of the last 9 samples, used only with 3 or more, bounded 0.5x–2.5x. `packDay({ learned })` uses it for new blocks (`rhythmBot` passes `learnedTime(t, estimateMinutes(t), times)`, learned from days before today) and a one-task block's why line says "usually takes you 1h40" (shown by `blockWhy`). Your own numbers win: a Todoist duration or a length you told Ben gives no learned time; the learned time also replaces the older per-kind multiplier (`benLearn`) for that task. Partly, Tomorrow and Drop teach nothing about length; nor do batches of several tasks.
  - **Plan score (`core/planScore.ts`).** One number 0–100 per checked day: 50% minutes done of minutes planned (each block counts up to its length; Partly its minutes, half the block without a number) + 30% blocks done in their time (real minutes at most 1.25x the plan, or no number) + 20% blocks that didn't slip or drop. It judges the plan, not effort; a day nobody checked has no score; no points.
